# CodeMetrics.AI 2.3.1

This patch corrects source populations, package metadata handling and contextual
findings observed across eight public .NET repositories. It targets .NET 10, emits
schema 3 and uses ruleset `dotnet-2026-09-15-declared-async-boundaries`.

## Accuracy and scope

- Security source findings and dependency observations count authored sites and
  package identities without multiplying penalties across target frameworks.
  Production vulnerability scope remains distinct from development dependencies.
- Explicit anonymous-access intent is honored. Bounded regex-only constants are
  distinguished from credentials, while unknown and mixed uses remain findings.
- Benchmark recognition and compilation diagnostics better respect project roles.
- NuGet metadata and package-asset inspection handle observed feed and archive
  layouts more accurately. Unavailable evidence still withholds the affected score;
  a failed assessment never becomes a clean result.
- Completed-task recognition includes supported short-circuit and switch guards.
  Recognized synchronous scripting callbacks and adjacent explanations of same-task
  waits remain informational review leads in async and error-handling findings.
  These classifications honor declared intent; they do not establish runtime safety.

## Async/Blocking Usage

The display name **Async/Blocking Usage** replaces **Performance & Async**.
It evaluates asynchronous operations and blocking calls for avoidable hazards,
accounting for documented intent and supported usage patterns. Scores reflect code
usage, not runtime speed or throughput. I/O latency, rate limits and deliberate
throttling do not inherently indicate misuse.

The stable evidence key remains `performanceAsync`. The numerical scoring ladder
is unchanged. The experimental percentage-of-affected-functions ladder is **not**
included in this release.

## Adoption and compatibility

Update with `dotnet tool update --global CodeMetrics.AI --version 2.3.1` (use
`install` for a first installation). The coordinated `ai_tools` skill update pins
2.3.1, uses the new display name, and preserves component explanations, streaming
execution and explicit assessment-failure reporting.

The npm evidence inspector remains `codemetrics-ai` 0.3.0; no npm release is needed.
Schema keys, CMAI identities and the raw CSV format remain compatible. Population
and classification corrections can change scores on unchanged source, so generate
fresh baselines rather than gating against the 2.3.0 ruleset.

See the [public corpus record](../../shared/scorecard-schema/calibration-runs/dotnet-public-corpus-2026-09-15.md)
and [declared-boundary verification](../../shared/scorecard-schema/calibration-runs/dotnet-declared-async-boundaries-2026-09-15.md)
for measured results and limits. Public corpus observations supplement regression
fixtures; they do not establish a universal quality ranking.
